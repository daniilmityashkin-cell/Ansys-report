# Сайт «замеры → геометрия → отчёт»: план

Цель: заказчик заходит на сайт, вводит данные по резервуару, жмёт «Сгенерировать», оплачивает и получает геометрию и модель с нагрузками.
Технический отчёт — по подписке, в личном кабинете, где хранятся все его генерации. Работает на физическом сервере (без облака).

## Что уже есть в репозитории и переиспользуется
- `ansys_report/geometry/` — проверка замеров по допускам, восстановление стенки, экспорт STEP/IGES, рисунки, Word-отчёт (6 секунд на резервуар). Это «рабочая лошадка» сайта.
- `ansys_report/word_gen.py`, `universal.py` — Word-отчёты по расчёту (нужны результаты Ansys).
- `ansys_scripts/` — выгрузка результатов из Ansys Mechanical (запускается у того, у кого есть Ansys).

## Этапы
1. **Каркас сайта**: регистрация и вход, форма ввода (вставка таблицы из Excel + загрузка JSON), хранение генераций, очередь задач, предпросмотр.
2. **Оплата разовой генерации**: платёжный провайдер, вебхуки, выдача файлов только после оплаты.
3. **Модель с нагрузками**: скрипт научного руководителя подключается как модуль «нагрузки и граничные условия» (ждём от него).
4. **Подписка и технический отчёт**: подписка с продлением, личный кабинет, история генераций.
5. **Эксплуатация**: HTTPS, резервные копии, мониторинг, логи, обновления.

## Предлагаемый стек (всё на Python, один сервер)
- Веб: FastAPI + шаблоны Jinja (страницы без тяжёлого фронтенда), позже можно усложнять.
- БД: PostgreSQL (для старта допустим SQLite), миграции Alembic.
- Задачи: отдельный рабочий процесс (очередь на Redis или таблица задач в БД), вычисления вне процесса сайта.
- Хранение файлов: каталог на диске + запись в БД; выдача по подписанным ссылкам.
- Пароли — argon2, подтверждение почты по SMTP, CSRF, лимиты запросов, проверка размера и формата загрузок.
- Развёртывание: Linux, nginx как обратный прокси, сертификат Let's Encrypt, systemd, резервные копии БД и файлов по расписанию.

## Платежи
- Нужны юрлицо, ИП или самозанятый (для российских провайдеров: ЮKassa, T-Bank, CloudPayments, Robokassa).
- Данные карт на нашем сервере не обрабатываются и не хранятся: оплата на странице провайдера, мы получаем вебхук.
- Вебхук принимаем на публичном адресе по HTTPS; статус платежа перепроверяем запросом к API провайдера (подписи или повторные запросы).
- Для публичного адреса нужны домен и доступ из интернета к серверу (белый IP или проброс порта; через университетскую сеть — согласовать с ИТ).

## Риски и условия
1. **Лицензия Ansys.** Академическая лицензия не допускает коммерческого использования. Если сайт будет запускать Ansys на сервере для платных заказчиков, нужна коммерческая лицензия с правом такого использования. Безопасный вариант: сервер Ansys не запускает; результаты Ansys заказчик выгружает у себя нашей программой (архив CSV и картинок) и загружает на сайт для отчёта.
2. **Права на скрипты.** Скрипт научного руководителя используется с его разрешения; для коммерческого сайта нужен письменный договор об авторстве и условиях (кто владелец, доли, лицензия университета).
3. **Персональные данные** (регистрация): хранение в РФ, политика конфиденциальности, согласие на обработку — по 152-ФЗ. Свой сервер в РФ для этого подходит.
4. **Надёжность физического сервера**: ИБП, резервный канал, регулярные бэкапы вне сервера, мониторинг доступности, план восстановления.
5. **Юридически значимые отчёты**: в документе должно быть сказано, что это результат автоматизированного расчёта, а не заключение эксперта (формулировку согласовать с юристом).

## Открытые вопросы (нужны решения)
1. Что именно получает заказчик за разовую оплату: геометрию (STEP/IGES) или также готовую модель Ansys с нагрузками? Какие входные данные сверх замеров (плотность продукта, уровень налива, снег, ветер, избыточное давление и т. д.)?
2. Откуда берутся результаты для технического отчёта: заказчик загружает выгрузку из своего Ansys, или расчёт идёт на нашем сервере?
3. Платёжный провайдер и юридическое лицо для приёма платежей.
4. Параметры сервера: ОС, процессор, память, диск, внешний IP и домен.
5. Тарифы: цена разовой генерации, цена подписки, что входит в подписку (число отчётов в месяц).
