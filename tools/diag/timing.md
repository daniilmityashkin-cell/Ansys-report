# Время сквозного прогона РВС-10000 по этапам (tools/e2e_local.py)

Метки: `C:\ansys_report_work\timing.log` (помощник, журналы Workbench, build_model.py, export_*.py); таблица - `python tools/timing_report.py`.
Этап = от своей метки до следующей. Решатель MAPDL - секунды; время уходит на Workbench/Mechanical.

## До ускорений (база, 27.10 00:00, 20,3 мин = 1220 с)

| Этап (группа) | секунд | % |
|---|---|---|
| Построение сетки: модель / идеальный РВС | 252 / 213 | 20,6 / 17,5 |
| Решения: модель (5 статик + Eigenvalue) / идеальный (2 + Eigenvalue) | 284 / 136 | 23,3 / 11,1 |
| Workbench сборка: Refresh геометрии + запуск Mechanical (модель / идеальный) | 77 / 38 | 6,3 / 3,1 |
| Выгрузка по поясам, результаты, картинки (модель + идеальный) | ~75 | ~6 |
| Запуски Workbench (4 раза по 16-22 с), закрытие, агент, diag | ~120 | ~10 |

Три самых долгих: **сетка (465 с, 38 %)**, **решения (420 с, 34 %)**, **идеальный РВС целиком (~450 с, 37 %, пересекается с первыми двумя)**.

Причины:
- сетка: mapped-сетка (Face Meshing) на кольце окрайки, добавленная для РВС-30000, стоила +230 с на модель и +195 с на идеальный РВС
  (без неё 25 / 18 с; замер на одной модели: tools/diag - диагностика diag_meshtime, варианты A/B/C/E);
- решения: в каждом статическом решении ~14 с /PREP7 - поэлементный цикл *DO по ~93 тыс. элементов для толщин поясов;
- идеальный РВС считается заново в каждом прогоне, хотя зависит только от номинальной геометрии, нагрузок и скриптов.

## Ускорения (сделано) и выигрыш

| Ускорение | Что изменено | Выигрыш |
|---|---|---|
| Mapped-сетка окрайки только при сбое сетки | build_model.py: сначала обычная сетка; ошибка «failed to mesh» -> mapped на кольце и повтор | **~7,1 мин** (сетка 252 -> 24 с и 213 -> 15 с) |
| Толщины поясов через ESEL,R,CENT вместо цикла *DO | build_model.apdl_thickness | **~1,5 мин** (каждое статическое решение 43 -> 30 с, 7 решений); результаты совпали до 0,01 МПа |
| Картинки только для отчёта | ANSYS_REPORT_IMAGES: report (наливы и дубли не снимаются), none для идеального РВС | **~0,5 мин** |
| Кэш идеального РВС | agent._ideal_cache: хэш файлов пакета (STEP - без заголовка с датой) и ansys_scripts | **~4,3 мин** при повторном прогоне того же резервуара |
| Блокировка помощника, чистая папка пакета | agent.lock с PID; pkg_<id> очищается | надёжность (второй запуск с сайта портил первый) |

Итог: **20,3 мин -> 11,9 мин** (первый прогон резервуара) **-> 7,6 мин** (повторный, идеальный РВС из кэша).
Результаты отчёта прежние: пояса 1-3 326,5 / 615,4 / 573,9 МПа, k1 = 1,5575, допустимый налив 13,1 м.

## Что ещё можно (не сделано)

- Одна сессия Workbench на сборку и выгрузку (сейчас Open_in_Ansys и Make_report открывают Workbench и Mechanical заново): ~1 мин.
  Нужна перестройка цепочки (Make_report у заказчика запускается отдельно) - решение владельца.
- Нагрузки в каждом решении тоже ставятся поэлементным циклом *DO (SFE по высоте центра): можно перевести на ESEL по поясам ветра
  и SFGRAD для гидростатики, но это меняет способ задания давления (по узлам, а не по центру элемента) - нужна сверка с Excel.
- Eigenvalue: 3 формы, в отчёт идут 2 - выигрыш небольшой (несколько секунд).
- РВС-30000: mapped-сетка кольца окрайки всё ещё нужна и стоит ~15 мин; правильное решение - разбить кольцо окрайки в STEP на секторы
  (assembly.py), чтобы PrimeMesh сетил его сам.
