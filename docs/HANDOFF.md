# Передача сессии (на 2026-10-26)

Ветка: `claude/ansys-report-automation-8asxtm` (последний коммит - слияние `local/ansys-debug`). Читать вместе с `CLAUDE.md`.

## Что работает
- Сайт `server/` (FastAPI, тёмный дизайн). Единый вход - студия `/studio` (7 шагов): 01 замеры (перетащить .json проекта «РВС Геометрия» или .xlsx геодезии - всё заполняется само, лист «пустой» выбирается сам), 02 профили образующих, 03 вмятины (сетка 9x11, вставка из Excel, «колоколом»), 04 3D восстановленной стенки, 05 конструкция (днище, крыша, каркас, патрубки-карточки), 06 ветровые кольца, 07 экспорт STEP (Стенка по поясам, Днище и окрайка, Крыша, Модель целиком). `/new` и `/new/table` ведут в студию.
- Страница расчёта `/g/{id}`: нагрузки задаются ПОСЛЕ создания модели (карточка «Нагрузки»), затем «Собрать отчёт» → помощник на ПК (`python -m ansys_report agent`) → Ansys → Word/Excel на сайт.
- Ansys: 5 случаев (эксплуатация, вакуум+снег+ветер пустой, налив 3 уровня), линейный, сетка 200 мм, балки BEAM188 (каркас крыши, опорное кольцо, ветровые кольца на границах поясов), буклинг, идеальный резервуар, допустимая высота налива (13,9 м на тестовом баке).
- Отчёт: раздел 6.2 - аналитическая проверка устойчивости по методике Excel ГОСТ 31385 (`ansys_report/loads/rvs_loads.py` сверен с таблицей).
- Узел «стенка–крыша»: конец радиальной балки через RBE3 на группу узлов + опорная полоса крыши (сделано локальной сессией): max 177,9 → 112,1 МПа, k1 1,44 → 1,55, перемещение 31,6 → 22,7 мм (`tools/diag/wall_roof_joint_before_after.md`).
- Инструменты: `dev.bat` (сайт с автоперезапуском), `tools/e2e_local.py` (сквозной прогон: сайт → Ansys → отчёт одной командой), `CLAUDE.md`, `.claude/settings.json`.

## Решения владельца

## Сделано 26.10 (сверх списка выше)
- CAD-сетка: `check.make_cad_adaptive` - крупный РВС с мелким шагом замеров больше не падает на «слишком большая CAD-сетка» (допуск и шаг сетки растут по ступеням); тест.
- Сгущение сетки 100 мм у вмятин по умолчанию (`ANSYS_REPORT_DENT_MESH_MM`, отступ 800 мм от кромки и днища): РВС-10000 допустимый налив 13,9 → 13,1 м, пояс 12 = 115 МПа (сходимость узла «стенка–крыша»: tools/diag/wall_roof_mesh_convergence.md; мембранные сходятся ~76 МПа, пик σ_экв на изломе - свойство упрощённой модели).
- Линии сетки на картинках убраны (`ExtraModelDisplay=NoWireframe`); `diag.bat` работает через `git worktree` в `C:\ansys_report_work\diag_wt`.
- Каталог профилей: `ansys_report/loads/profiles.py` (ГОСТ 8239 двутавры 10…60, ГОСТ 8240 швеллеры 5…40, ГОСТ 8509 уголки; плюс «по габаритам»: Двутавр H×B×s×t, Швеллер, Уголок, Труба, Полоса; «Свои A= Ix= Iy=»). Студия: подсказки в списке и свойства под полем, профили из файла проекта принимаются как есть. Профиль серии Б и т.п. - только габаритами (в каталоге нет). Раньше сечения, введённые руками, до Ansys не доходили (беамы брались только из файла проекта): теперь `beams.with_structure_sections` достраивает проект из structure.json.
- «Изменить геометрию»: ссылка на странице генерации (`/studio?edit=<id>`, `/studio/edit/<id>`); замеры, конструкция, ветровые кольца возвращаются в студию, при «Создать модель» создаётся НОВАЯ генерация (нагрузки вводятся заново).
- Толщины поясов обязательны: геодезия .xlsx и идеальный резервуар больше не подставляют 10 мм молча; студия не пускает дальше шага 01, сервер (`tableinput.require_thicknesses`) отклоняет модель без толщин.

- Нагрузки на модели (27.10): карточка «Нагрузки на модели» на странице расчёта (`/g/{id}`, `server/static/loads3d.js`, `/g/{id}/loads3d.json`): по каждому случаю отчёта (эксплуатация, вакуум+снег+ветер, 3 уровня налива) давление на стенку/крышу/днище цветом и стрелками, обновляется по мере ввода в форму (POST без сохранения). Формула та же, что в `apply_loads.py` (`export.pressure_view`, тест).
- Студия: широкая вёрстка (до 1900 px), колонка толщин закреплена справа, одинаковые карты вмятин, «Выбрать файл» - главная кнопка, название берётся из каждого загруженного файла.
- Помощник без окон консоли: `agent.launch` через pythonw (реестр: `python -m ansys_report agent --install` нужно выполнить заново), `CREATE_NO_WINDOW` для cmd/RunWB2, ошибки - окном сообщения и `agent.log`.

## Как работать на ПК владельца
- Окно 1: `cd C:\Ansys-report; .\dev.bat` (сайт). Окно 2: `cd C:\Ansys-report; claude` (локальный ассистент, подключён pymechanical-mcp; для Mechanical реально работает запуск Workbench батч-журналом `RunWB2 -B`).
- Облачная и локальная сессии не должны одновременно править одну ветку: локальная пушит в `local/ansys-debug`, облачная сливает.
- Диагностика прогонов - ветка `diag-logs` (`diag/diag.txt`, `diag/report.docx`).
