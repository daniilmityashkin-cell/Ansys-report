# ANSYS REPORT: памятка для ассистента

Продукт: пакет `ansys_report` (генерация технического отчёта Word/Excel по расчёту стального вертикального резервуара РВС в Ansys) и сайт `server/` (FastAPI).
Поток: заказчик загружает замеры (проект «РВС Геометрия» .json / геодезия .xlsx / вручную) → студия `/studio` (шаги 01–07) → страница расчёта `/g/{id}`: нагрузки → «Собрать отчёт» → помощник на ПК заказчика (`python -m ansys_report agent`) строит модель в Ansys Workbench/Mechanical, считает, возвращает Word/Excel на сайт.

## Правила работы
- Отвечать по-русски, коротко; команды для PowerShell давать готовыми блоками для копирования, без «найдите папку».
- Ветка разработки: `claude/ansys-report-automation-8asxtm`. PR не создавать без просьбы.
- Отчёт и логи прогона проверять самому: ветка `diag-logs` (`diag/diag.txt`, `diag/report.docx`), `git fetch origin diag-logs; git show origin/diag-logs:diag/diag.txt`.
- Секреты в репозиторий не класть. Скрипт научника («РВС Геометрия») не распространяется; мы повторяем его поведение своим кодом.

## Единицы и методики
- Ansys Mechanical: Н, мм, МПа. Давление: «+» внутрь стенки (наружу от оси), вакуум/снег/ветер — отрицательные.
- Нормы: ГОСТ Р 58622-2019 (структура отчёта, прочность 1,5[σ] по мембранным напряжениям, устойчивость k), ГОСТ 31385-2016 (аналитическая методика; Excel: `ansys_report/loads/rvs_loads.py` сверен с таблицей, проверка в `tests/`).
- Устойчивость пустого резервуара - схема эталона Т-001 (`tools/diag/etalon_T001_wb.md`): нелинейная статика (большие перемещения) с ветром-возмущением w0 вектором по всей стенке, направления Y и Z, затем Eigenvalue Buckling (2 моды), требуемый k = 10 (рекомендуемый 10…15). При заданном весе крыши F (данные отчёта) F, изоляция крыши и снег - силой на верхнюю кромку стенки, крыша без плотности; сталь (E, ν, ρ) - из данных отчёта.
- Расчёт линейный по умолчанию (`ANSYS_REPORT_LARGE_DEFLECTION=1` включает большие перемещения; не сходилось).

## Ansys (скрипты IronPython 2, `ansys_scripts/`)
- Без f-строк; `exec` только на уровне модуля; APDL через `AddCommandSnippet` (EXTRA_APDL начинается с `/PREP7`, заканчивается `/SOLU`).
- Модель: одна оболочка из STEP (стенка по поясам + днище + окрайка + крыша), тела `p1..pN`, `dno`, `okrayka`, `krovlya`; именованные выборки `AR_WALL/AR_ROOF/AR_BOTTOM/AR_ANNULAR/AR_BASE_EDGE`.
- Балки (BEAM188): каркас крыши и опорное кольцо из `beams.json`, ветровые кольца на границах поясов.
- Окружение: `AR_WORK` (рабочая папка), `AR_NODIAG`, `AR_NOPAUSE`, `ANSYS_REPORT_MESH_MM` (200), `ANSYS_REPORT_DENT_MESH_MM` (100: сгущение сферой у вмятин из `dents.json`, 0 - выкл.), `ANSYS_REPORT_HOME`.
- Известные открытые вопросы: узел «стенка–крыша» (12-й пояс 150–210 МПа почти во всех случаях), линии сетки на картинках результатов (`prep_results_view`: `ExtraModelDisplay` через отражение).

## Проверки
- Без Ansys: `python -m pytest tests -q` (серверные тесты долгие: `tests/test_server.py` ~2 мин).
- Сайт локально: `python -m server` (порт 8000, `ASR_*` переменные в `server/config.py`).
- Новые вещи покрывать тестами с известными числами (сверка с Excel), не менять единицы без причины.

## Рабочий цикл на ПК владельца (локальный Claude Code)
- Два окна PowerShell: 1) `cd C:\Ansys-report; .\dev.bat` (сайт на http://127.0.0.1:8000 сам перезапускается при правке .py; шаблоны и стили видны после обновления страницы); 2) `cd C:\Ansys-report; claude` (ассистент правит файлы в этом же каталоге, `git pull` не нужен).
- Владелец описывает проблему словами или скриншотом, ассистент правит код, проверяет (`python -m pytest tests -q -k <тема>`, сквозной прогон `python tools/e2e_local.py --project <проект.json>`), и по просьбе коммитит и пушит в ветку `local/ansys-debug` (в `claude/ansys-report-automation-8asxtm` пушит только по просьбе владельца).
- Скрипты Mechanical проверять на копии проекта в `C:\ansys_report_work`, лицензию занимать на минимум.
